Dataset schema and annotation coverage

Observed 2026-10-16 using owner-authenticated Viewer first-row/schema and size endpoints. Configurations have different row meanings; their row counts must not be combined into a count of independent examples. The technical split name train is retained for API compatibility in all configurations and is not an authored benchmark partition.

Configuration Row meaning Reported rows
videos One recording with seven camera slots 1,469
camera_annotations One sampled camera frame with weak pseudo-labels 34,306
gnss One decoded GNSS message 18,373,026
semantic_depth One sampled frame with display previews 34,306

A control-file audit on 24 October 2026 checked all 34,306 camera-annotation Viewer rows and dense indexes: distinct frame IDs and camera/time and camera/frame-index keys are unique; no annotation refers to an absent video stream. Labels occur in 3,169 of 9,927 streams, leaving 6,758 without labels. Dense indexes contain 34,306 semantic and 34,306 depth references matched to the annotation identities. This is not a complete join audit against all source camera-frame tables or decoded videos. See per-stream coverage and summary with input hashes. Semantic class IDs/fractions and the listed aggregate fraction fields are auxiliary machine-generated signals, not a human-verified ontology-coverage result. Weather scores are not validated probabilities, and metric-depth outputs are not measured depth ground truth.

Camera annotation and semantic/depth configurations expose recording_id, camera_name, selected_time_of_day_ns, recording_offset_ns, frame_index, and frame_id. Use the dense index to resolve archive members; inspect uniqueness and missing joins before matching tables. No per-class accuracy, detector recall, or privacy QA score is asserted.

The GNSS Viewer flattens coordinate fields. See sensor conventions for timestamp namespaces, per-recording local ENU, invalid rows with coordinates, and unresolved source-stream composition.

Source tables and sampling folders

The column dictionary documents all normalized source-table families. Annotation folders now use sample_group=. The Parquet split column remains a legacy sampling-group field; Viewer technical train splits remain API-compatible. The path migration map records content-preserving moves.

GNSS source tables retain channel (gnss / rec_gnss); the existing flattened Viewer does not. Use source tables for channel-specific rate/trajectory analysis. Combined source-documentation counts are 15,317,896 and 3,055,130, respectively.

Source annotation row-count audit

Metadata-only Parquet footer inspection at 473b9ea659064ac13f63b11b9d6b77829ded6b6d counted 34,306 rows across all 1,469 source frame-label files. The Viewer reports 34,306 rows. Row counts are not a distinct-frame count or a guarantee of complete joins.

Producer-confirmed seven-camera extrinsics

Every existing camera row in data/tables/calibrations/ adds the non-null calibrated_extrinsics struct. Original columns and source JSON remain unchanged. This includes explicit camera identity, signed yaw/tilt, rig and front-reference camera centres in millimetres, and row-major homogeneous transforms with named direction. The tilted front camera is +4 degrees downward. The rig axes are X left, Y forward, Z up; the front reference subtracts [0,0,1546] mm and is not an optical frame. See the complete schema, equations, provenance and join rules. Existing source schema_version values are retained; the additive model is identified by its own calibration_id.

Devkit camera timing and partial recordings

For every recording, the devkit defaults to camera payload rec_timestamp (rec_time_offset_ns) for camera selection, synchronization and exported times, and main gnss payload timestamp (time_offset_ns) for GNSS. Untimed quality-flagged GNSS messages define excluded gaps; leading portions can be trimmed from an export without rejecting the whole recording. Raw table fields and annotation source identities are unchanged. See exact fields and trimming policy.
